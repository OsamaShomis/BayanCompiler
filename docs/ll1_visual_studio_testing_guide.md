# دليل اختبار Compiler Journey وLL(1) في Visual Studio وMARS

> **نطاق الدليل:** الاختبار النهائي لمحرر Windows Forms يجري على Windows باستخدام Visual Studio 2022. يستخدم المحرر `Bayan.Compiler.Cli` مستقلاً، ثم يعرض artifacts التي كتبها CLI فعلياً. لا ينفذ المحرر Lexer أو Parser أو MIPS داخله مباشرة.

## 1. فتح الحل وبناؤه

1. فك الحزمة في مسار إنجليزي قصير، مثل `C:\BayanCompiler`.
2. افتح `Bayan.sln` من جذر المشروع في Visual Studio 2022.
3. اجعل مشروع `Bayan.Editor.WinForms` مشروع البدء.
4. اختر **Build → Clean Solution**، ثم **Build → Rebuild Solution**.
5. شغّل المشروع. تظهر شاشة ترحيب «بيان»، ثم تدخل إلى مساحة **Compiler Journey**.

لا تفتح مشروع المحرر منفرداً عند فحص التكامل؛ فـCLI يبنى وينسخ بجانب المحرر من خلال مراجع الحل.

## 2. رحلة الترجمة التي يجب ظهورها

بعد فتح ملف `.bayan` رسمي والضغط على **تحليل وترجمة**، راجع المراحل بالترتيب التالي:

| المرحلة في الواجهة | artifact الفعلي من CLI |
| --- | --- |
| Tokens / AST | `tokens.txt` و`ast.txt` |
| جدول LL(1) | `ll1-table.txt` |
| تتبع LL(1) | `ll1-trace.txt` |
| شجرة التحليل | `parse-tree.txt` |
| جدول الرموز | `symbol-table.txt` |
| TAC / IR | `three-address-code.txt` |
| MIPS | `program.asm` |
| التشخيصات | `diagnostics.txt` أو رسالة تشغيل واضحة عند تعذر CLI |

عند نجاح الترجمة يصل المستخدم إلى مرحلة MIPS. عند الفشل تنتقل الواجهة إلى التشخيصات، ولا ينبغي أن تدّعي الواجهة أن MIPS تم توليده.

## 3. عينات القواعد الرسمية

العينات الرسمية هي من `11` إلى `25`. لا تستخدم العينات `01` إلى `10` كمعيار قبول؛ فهي مواد مؤرشفة من مسار سابق ولا تمثل الصياغة الرسمية الحالية.

| الملف | الإجراء | النتيجة المتوقعة |
| --- | --- | --- |
| `12_official_basic_execution.bayan` | تحليل وترجمة | `Success = true` و`CompletedStage = MIPS` وبدون diagnostics. |
| `13_doctor_loops_execution.bayan` | تحليل وترجمة | ظهور TAC وMIPS للحلقات الرسمية. |
| `15_power_and_integer_division.bayan` | تحليل وترجمة | توليد مسار الأس والقسمة الصحيحة. |
| `17_character_type_execution.bayan` | تحليل وترجمة | دعم النوع الحرفي في artifacts وMIPS. |
| `18_lists_and_records_execution.bayan` | تحليل وترجمة | ظهور نتائج القوائم والسجلات المباشرة. |
| `20_real_type_execution.bayan` | تحليل وترجمة | دعم النوع الحقيقي ومخرجات FPU. |
| `25_symbolic_string_input.bayan` | تحليل وترجمة | دعم الخيط الرمزي وإدخاله. |

## 4. اختبار خطأ نحوي رسمي

انسخ `12_official_basic_execution.bayan` إلى ملف جديد، ثم احذف فاصلة منقوطة رسمية واحدة من التعريف أو التعليمة. بعد الضغط على **تحليل وترجمة** يجب أن تنتقل الواجهة إلى مرحلة **التشخيصات** ويظهر `SYN001` أو التشخيص النحوي المقابل. لا يجب إنشاء `program.asm` في هذه الحالة.

## 5. اختبار MIPS في MARS أو JsSpim

1. افتح `12_official_basic_execution.bayan` داخل Compiler Journey.
2. اضغط **تحليل وترجمة** حتى تظهر مرحلة **MIPS Assembly**.
3. اضغط **حفظ MIPS** واحفظ الملف بامتداد `.asm`.
4. افتح الناتج في MARS أو JsSpim ثم نفّذ Assemble وRun.
5. قارن السلوك مع نتيجة العينة المتوقعة في الاختبارات الرسمية.

## 6. قرار القبول

لا يكتمل التحقق إلا إذا تحققت البنود التالية:

- [ ] نجاح Rebuild Solution في Visual Studio 2022.
- [ ] ظهور شاشة الترحيب ثم Compiler Journey من دون قص أو تداخل.
- [ ] نجاح `12_official_basic_execution.bayan` حتى MIPS.
- [ ] ظهور artifacts الثمانية في مراحلها الصحيحة.
- [ ] انتقال العينة النحوية المحرّفة إلى التشخيصات دون ادعاء نجاح.
- [ ] حفظ MIPS وتشغيله في المحاكي المناسب عند الحاجة.
- [ ] فحص النافذة بأحجام صغيرة ومتوسطة وكبيرة وتوثيق أي قيد متبقٍ.
