# تحقق إعادة تصميم محرر «بيان»

## ما تم فحصه

| الفحص | النتيجة |
| --- | --- |
| صياغة C# لملفات `Forms` | نجحت عبر Roslyn: 6 ملفات بلا أخطاء صياغة. |
| بنية المحطات | 5 محطات رئيسية: المصدر، التحليل، التمثيل الوسيط، الأهداف، النتيجة. |
| المساحة المركزية | تعتمد سطح محتوى واحداً لكل مرحلة؛ لا توجد `SplitContainer` أو 12 زر مرحلة في صف واحد. |
| سلوك CLI | بقيت القراءة من artifacts الحقيقية عبر `CliCompilationClient`. |
| بناء Core | نجح بلا تحذيرات أو أخطاء. |
| بناء CLI | نجح؛ تحذير `NETSDK1138` فقط بسبب `net6.0` خارج الدعم. |
| اختبارات LL(1) الرسمية | نجحت **26/26**. |
| بناء محرر WinForms في Linux | توقف عند `MSB4019`: غياب `Microsoft.NET.Sdk.WindowsDesktop.targets` من البيئة، قبل تحليل C# أو إنشاء المحرر. |

## فحص Windows المطلوب

لا يمكن اعتماد الفحص البصري أو السلوكي النهائي إلا من Windows. بعد فتح الحزمة في Visual Studio 2022، يُنفذ **Clean Solution** ثم **Rebuild Solution**، وتفحص النافذة عند العرض الأدنى `940px`، وعرض متوسط، وعرض كبير.

ينبغي التحقق من أن المحطات الخمس موزعة في صف واحد بلا تمرير أفقي، وأن قائمة المحطة الفرعية تعرض محتوى المحطة المختارة فقط، وأن أزرار MIPS وEXE لا تظهر إلا في محطة الأهداف. كما يجب التأكد من تعطيل **تنفيذ EXE** قبل إنشاء `program.exe`، ومن ظهور stdout في محطة النتيجة بعد التنفيذ الناجح.

> نتيجة Linux لا تثبت تشغيل Windows Forms أو مظهره. الدليل الحالي يثبت صحة الصياغة وفصل مسار Core وCLI، ويبقى Rebuild وفحص النافذة الفعلي على Windows شرطاً مفتوحاً.
