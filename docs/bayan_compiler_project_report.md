## 1. الملخص التنفيذي

يقدم هذا المشروع مترجماً متكاملاً وعملياً للغة البرمجة العربية «بيان» وفقاً لمواصفات وتوجيهات المقرر الرسمية. 
لا يكتفي المترجم بمجرد محاكاة للترجمة، بل ينفذ خط أنابيب حقيقي كامل ينقل كود المصدر العربي عبر 9 مراحل أكاديمية وتنفيذية دقيقة ومستقلة، منتقلاً من النص البرمجي إلى التحليل اللغوي، فالتحليل النحوي التنبئي LL(1)، والتحليل الدلالي وجداول الرموز، مروراً بالتمثيل الوسيط ثلاثي العناوين (Three-Address Code)، وصولاً إلى إنتاج كود تجميعي (x86 Assembly) وتوليد كود لغة الآلة الوسيطة (CIL) وتجميعه آلياً في **ملف تنفيذي حقيقي ومستقل بنسق PE Executable (.exe)** قابل للتشغيل المباشر على نظام ويندوز.

يتميز المشروع بـ:
1. **الالتزام الكامل بالقواعد النحوية الرسمية**: دعم كامل لتعريف الثوابت (`ثابت`)، الأنواع المخصصة (`نوع`)، المتغيرات (`متغير`)، الأنواع الأولية (`صحيح`, `حقيقي`, `منطقي`, `حرفي`, `خيط رمزي`)، والأنواع المركبة كالـ `سجل` و `قائمة من`، مع إجراءات فرعية تقبل التمرير بالقيمة (`بالقيمة`) أو المرجع (`بالمرجع`).
2. **واجهة رسومية ذات 9 مراحل صارمة**: خالية تماماً من تداخل العناصر (مبنية بواسطة `TableLayoutPanel`)، توفر تتبعاً مرئياً مباشراً لشجرة الإعراب، جدول LL(1)، خطوات اشتقاق المكدس (Stack Trace)، جدول الرموز، كود TAC، وشاشة تنفيذ تفاعلية تدعم الإدخال الحي بأمر `اقرأ`.
3. **أداة سطر أوامر مستقلة (CLI)**: تتيح ترجمة أي برنامج بملف واحد وإخراج تقارير التحليل والملف التنفيذي.
4. **تغطية اختبارية شاملة**: حزمة اختبارات ذاتية تغطي 25 حالة اختبار معتمدة بنسبة نجاح 100%.

## 2. المفردات اللغوية والأنواع المعتمدة (Lexical Specification)

### 2.1 الكلمات المفتاحية المحجوزة
تعتمد لغة بيان الكلمات المفتاحية باللغة العربية بدقة، وتشمل:
* **الهيكل والتحكم بالبرنامج**: `برنامج`، `ثابت`، `نوع`، `متغير`، `إجراء`.
* **تمرير المعاملات**: `بالقيمة`، `بالمرجع`.
* **الأنواع المركبة**: `سجل`، `قائمة`، `من`.
* **التحكم والشروط**: `إذا`، `فإن`، `وإلا`، `طالما`، `كرر`، `إلى`، `أضف`، `أعد`، `حتى`، `استمر`.
* **الإدخال والإخراج**: `اقرأ`، `اطبع`.
* **القيم المنطقية**: `صح`، `خطأ`.

### 2.2 أنواع البيانات الرسمية
| النوع العربي | المقابل البرمجي | الوصف والملاحظات |
|---|---|---|
| `صحيح` | 32-bit Signed Integer | الأعداد الصحيحة (مثل: `5`، `-12`) |
| `حقيقي` | 32-bit IEEE-754 Float | الأعداد العشرية الحقيقية (مثل: `3.14`، `0.5`) |
| `منطقي` | Boolean (1-bit / word) | القيم الثنائية (`صح` أو `خطأ`) |
| `حرفي` | Unicode Character | المحارف المفردة المحاطة باقتباس مفرد (مثل: `'أ'`، `'Z'`) |
| `خيط رمزي` | Dynamic String | السلاسل النصية المحاطة بعلامات تنصيص مزدوجة (مثل: `"مرحبا بيان"`) |
| `قائمة[N] من T` | Fixed-size Array | مصفوفة خطية ذات حجم ثابت مفهرسة من الصفر |
| `سجل { حقول }` | Composite Record/Struct | سجل مركب يضم حقولاً مسماة بأنواعها |

### 2.3 العوامل والعمليات (Operators & Punctuation)
* **العمليات الحسابية**: الجمع `+`، الطرح `-`، الضرب `*`، القسمة الحقيقية `/`، القسمة الصحيحة `\`، الأس `^`.
* **عمليات المقارنة والمنطق**: المساواة `==`، اللاتساوي `=!`، أصغر من `<`، أكبر من `>`، أصغر من أو يساوي `=<`، أكبر من أو يساوي `=>`، النفي `!`، العطف `&&`، والوصل `||`.
* **علامات الترقيم والأقواس**: الفاصلة المنقوطة `؛` (و `;`)، الفاصلة `،` (و `,`)، النقطة `.`، والأقواس بأنواعها `( )`، `[ ]`، `{ }`.

## 3. قواعد التحليل النحوي وجدول LL(1) (Grammar & LL(1) Parsing)

تم صياغة قواعد اللغة بصيغة خالية من التكرار اليساري المباشر وغير المباشر (Left-Recursion Free) مع تفكيك العوامل المشتركة (Left-Factoring) لتتوافق بدقة مع محلل LL(1) التنبئي المعتمد على جدول التحليل.

### 3.1 بنية القواعد الأساسية
```
1.  ProgramUnit           -> "برنامج" Ident ";" DefinitionList "{" StatementList "}" "."
2.  DefinitionList        -> Definition DefinitionList | ε
3.  Definition            -> ConstDef | TypeDef | VarDef | ProcDef
4.  ConstDef              -> "ثابت" Ident "=" Literal ";"
5.  TypeDef               -> "نوع" Ident "=" TypeSpecification ";"
6.  TypeSpecification     -> SimpleType | "سجل" "{" FieldList "}" | "قائمة" "[" IntLiteral "]" "من" SimpleType
7.  VarDef                -> "متغير" IdentList ":" TypeSpecification ";"
8.  ProcDef               -> "إجراء" Ident "(" ParamList ")" ";" ProcBody ";"
9.  StatementList         -> Statement StatementList | ε
10. Statement             -> AssignStmt | IfStmt | WhileStmt | RepeatStmt | DoUntilStmt | CallStmt | ReadStmt | PrintStmt
```

### 3.2 جدول التحليل النحوي والتتبع (LL(1) Parsing Table & Stack Trace)
يقوم المحلل ببناء المكدس النحوي:
* يبدأ المكدس بالرمز المبدئي ومحدد نهاية المدخلات: `[ProgramUnit, $]`.
* في كل خطوة، يستشير المحلل الخلية `M[NonTerminal, LookaheadToken]`.
* إذا وُجد إنتاج، يستبدل الرمز غير الطرفي برموز الإنتاج بالترتيب الصحيح.
* إذا كان الرمز طرفياً، يطابقه مع الرمز القادم (Match) ويتقدم في النص المصدري.
* يتم تسجيل وحفظ مسار التتبع الكامل (Stack, Input, Action) خطوة بخطوة في ملف `ll1-trace.txt` ويعرض حياً في المرحلة الخامسة من واجهة المحرر.

## 4. التحليل الدلالي وجدول الرموز (Semantic Analysis)

يقوم المحلل الدلالي (`DoctorSemanticAnalyzer`) بالمهام الآتية:
1. **إدارة جداول الرموز المتعددة النطاقات (Scoped Symbol Table)**:
   - نطاق عام (Global Scope) للثوابت والأنواع والمتغيرات والإجراءات.
   - نطاقات محلية (Local Scopes) لمحتويات الإجراءات والكتل البرمجية.
2. **التحقق من صحة التعريف والاستخدام**:
   - منع إعادة تعريف الرموز في نفس النطاق.
   - اكتشاف الأخطاء عند استخدام متغيرات أو إجراءات غير معرفة.
3. **مطابقة الأنواع والترقية التلقائية (Type Checking & Promotion)**:
   - التحقق من توافق الأنواع في جمل الإسناد والعمليات الحسابية والمنطقية.
   - السماح بالترقية التلقائية من `صحيح` إلى `حقيقي` عند الحاجة.
4. **التحقق من صحة المعاملات**:
   - مطابقة عدد وأنواع المعاملات الممررة في استدعاءات الإجراءات.
   - التحقق من تمرير متغيرات قابلة للتعديل (L-Values) فقط للمعاملات المعرفة `بالمرجع`.

## 5. الكود الوسيط ثلاثي العناوين (Three-Address Code - TAC)

يمثل كود TAC المرحلة الوسيطة المستقلة عن العتاد، حيث يُفكك أي تعبير معقد إلى سلسلة تعليمات عنوانية ثلاثية لا تحتوي أكثر من معاملين وعامل ونتيجة واحدة، مع أسماء تخزين آمنة (`var_x`, `temp_x`, `param_x`).

### أنواع تعليمات TAC المعتمدة:
* **الإسناد**: `Result = Left`
* **العمليات الثنائية**: `Result = Left Op Right`
* **العمليات الأحادية**: `Result = Op Left` (مثل السالب والنفي المنطقي)
* **التفرع والقفز**:
  - قفز غير مشروط: `اذهب إلى Label`
  - قفز شرطي: `إذا كان Condition = 0 اذهب إلى Label`
* **إدارة الإجراءات**:
  - وضع علامة الإجراء: `إجراء_X:`
  - الاستدعاء: `استدعِ إجراء_X`
  - العودة: `عودة`
* **الإدخال والإخراج**:
  - `اقرأ_عدد Target`, `اقرأ_حقيقي Target`, `اقرأ_نص Target`
  - `اطبع_عدد Value`, `اطبع_حقيقي Value`, `اطبع_نص Value`, `اطبع_حرف Value`
* **الوصول المفهرس للمركبات**:
  - القراءة من عنصر/حقل: `Result = Base[Offset]`
  - الكتابة في عنصر/حقل: `Base[Offset] = Value`

## 6. توليد كود التجميع والملف التنفيذي الحقيقي (Code Generation & EXE Creation)

لتحقيق متطلبات المشروع الأكاديمية والتطبيقية، يحتوي المترجم على مسارين متكاملين لتوليد الكود النهائي:

### المسار الأول: كود التجميع الأكاديمي (x86 Assembly)
* يقوم `AssemblyGenerator` بتوليد كود تجميعي بلغة x86 القياسية يضم أقسام البيانات (`section .data` للنصوص والثوابت العائمة)، والمتغيرات غير المهيأة (`section .bss` بحجز الكلمات `resd`)، والتعليمات البرمجية (`section .text`).
* يُحفظ الملف باسم `output.asm` ويُعرض في المرحلة الثامنة كمرجع للمقارنة ودراسة تصميم عمارة الحاسوب.

### المسار الثاني: الملف التنفيذي الحقيقي المستقل (`output.exe`)
* يُترجم نفس كود TAC إلى كود لغة الآلة العامة CIL المتوافق مع مواصفات ECMA-335 (.NET CIL).
* يتم تعريف المتغيرات والمعاملات كحقول ساكنة (`.field public static`), وتوليد دوال فرعية مستقلة للإجراءات (`.method public static void proc_X()`), ودالة رئيسية بنقطة دخول (`.entrypoint`).
* يُحفظ كود CIL في ملف `output.il`.
* يستدعي المترجم تلقائياً أداة مجمع النظام المعتمدة **`ilasm.exe`** لتجميع ملف `output.il` وتحويله مباشرة إلى **ملف تنفيذي حقيقي بنسق PE Executable (`output.exe`)**.
* ملف `output.exe` الناتج ملف ويندوز حقيقي قابل للتشغيل منفرداً من أي موجه أوامر بالنقر عليه مباشرة، ويتم تشغيله تفاعلياً داخل الواجهة الرسومية.

## 7. مراحل خط الأنابيب التسع في واجهة المحرر (The 9 Pipeline Stages)

تم ضبط وتوحيد واجهة المحرر لتقتصر على 9 مراحل مرقمة بدقة داخل `TableLayoutPanel` متناسق يضمن استقرار الرؤية وعدم تراكب النوافذ:

1. **المرحلة 1: الكود المصدري (Source Editor)**
   محرر نصوص برمجية يتيح كتابة وتحرير كود بيان، وفتح وحفظ ملفات `.bayan`، مع تسليط الضوء ورسائل المساعدة.
2. **المرحلة 2: التحليل اللغوي (Tokens Table)**
   جدول يعرض كافة الرموز المفردة المعالجة (نوع الرمز Token Type، النص المصدري Lexeme، السطر، والعمود).
3. **المرحلة 3: شجرة الإعراب (Parse Tree)**
   عرض تفاعلي هرمي للشجرة التركيبية الناتجة عن اشتقاقات القواعد النحوية.
4. **المرحلة 4: جدول التحليل النحوي LL(1) (LL1 Analysis Table)**
   جدول مصفوفي يوضح تقاطع كل رمز غير طرفي (Non-Terminal) مع الرموز الطرفية (Terminals) والإنتاج المطبق.
5. **المرحلة 5: تتبع التحليل النحوي LL(1) (LL1 Parsing Trace)**
   سجل تعقب لحظي للخطوات التي مر بها المحلل مع توضيح حالة المكدس وشريط المدخلات والعمليات.
6. **المرحلة 6: جدول الرموز الدلالي (Symbol Table)**
   جدول الرموز الشامل للمتغيرات، الثوابت، الإجراءات، والأنواع مع ذكر النطاق، النوع، ووضعية التمرير.
7. **المرحلة 7: الكود الوسيط TAC (Three-Address Code)**
   النص البرمجي للتعليمات الثلاثية مع خريطة مطابقة الأسماء العربية للأسماء الداخلية.
8. **المرحلة 8: كود التجميع المنخفض Assembly**
   كود تجميعي نقي (x86 Assembly) يطابق بنية البرامج المنخفضة المستوى.
9. **المرحلة 9: تنفيذ البرنامج (Program Execution & Live Console)**
   شاشة مدمجة لتشغيل ملف الـ EXE الناتج حياً، مع مستطيل إدخال مخصص لإرسال المدخلات عند استدعاء أمر `اقرأ`.

## 9. دليل التشغيل والتنفيذ (User & Execution Guide)

### 9.1 تشغيل الواجهة الرسومية (GUI Editor)
من مجلد المشروع، نفذ الأمر التالي:
```bash
dotnet run --project src/BayanCompiler/BayanCompiler.csproj
```
* تفتح واجهة المحرر ذات المراحل التسع.
* اضغط «فتح ملف» لاختيار أي ملف من مجلد `samples/`.
* اضغط «تحليل وترجمة» (أو مفتاح `F5`) لترجمة البرنامج وتشغيله فوراً.

### 9.2 استخدام مترجم سطر الأوامر (CLI)
لترجمة أي ملف مباشرة وحفظ جميع المخرجات:
```bash
dotnet run --project src/Bayan.Compiler.Cli/Bayan.Compiler.Cli.csproj -- samples/11_doctor_rules_integrated.bayan
```
تُحفظ كافة ملفات التحليل وملف `output.exe` في مجلد `bayan-results/`.
يمكنك تشغيل البرنامج الناتج مباشرة عبر:
```bash
.\samples\bayan-results\output.exe
```

### 9.3 تشغيل حزمة الاختبارات الذاتية (Automated Test Runner)
للتحقق من سلامة كافة مكونات المترجم:
```bash
dotnet run --project tests/BayanCompiler.Ll1Tests
```
النتيجة المتوقعة:
```
[PASS] جدول LL(1)
[PASS] التحليل اللغوي
[PASS] التحليل الدلالي
...
النتيجة: 25 / 25 اختبار ناجح (100%).
```

### 9.4 النشر كملف تنفيذي محمول (Publishing Standalone Portable App)
يحتوي المشروع على ملف البناء `publish.bat`. عند تشغيله:
```cmd
publish.bat
```
يتم إنتاج ملف تنفيذي محمول بالكامل بنسق Single-File Self-Contained في مجلد الـ Release:
`src/BayanCompiler/bin/Release/net6.0/win-x64/publish/BayanCompiler.exe`
يعمل هذا الملف على أي حاسوب يعمل بنظام Windows دون الحاجة لتثبيت بيئة .NET SDK مسبقاً.

## 10. الخاتمة والاستنتاجات

يمثل مشروع مترجم لغة «بيان» تطبيقاً هندسياً حقيقياً ومتكاملاً لعلم المترجمات الحديث. استطاع المشروع الربط بين متانة التحليل النظري (LL(1) Parsing والتحليل الدلالي المنضبط) وبين الفاعلية التطبيقية بإنتاج ملفات تنفيذية PE حقيقية قابلة للعمل مباشرة على أنظمة التشغيل، مقدماً نموذجاً تعليمياً عربياً راقياً وواجهة مستخدم احترافية ذات 9 مراحل واضحة وسلسة.
