# إعداد زر تنفيذ MIPS على Windows

## ما الذي يفعله الزر؟

زر **تنفيذ** لا يصنع ملف EXE ولا يعرض لغة الآلة. هو يشغّل ملف `program.asm` الذي ولّده مترجم CLI في محاكي MIPS خارجي، ثم يعرض النص الذي طبعه البرنامج في مرحلة **نتيجة التنفيذ** داخل المحرر.

## الخيار الأول: MARS

ثبت Java، ثم احفظ ملف `Mars.jar` في مسار ثابت. عيّن متغير البيئة للمستخدم باسم `BAYAN_MARS_JAR` إلى مسار الملف، مثل:

```text
C:\Tools\MARS\Mars.jar
```

عند وجود هذا المتغير، يشغّل المحرر الأمر `java -jar Mars.jar nc sm program.asm` تلقائياً.

## الخيار الثاني: SPIM

إذا لم تستخدم MARS، ثبت SPIM ثم عيّن متغير البيئة `BAYAN_SPIM_PATH` إلى الملف التنفيذي، مثل:

```text
C:\Program Files\SPIM\spim.exe
```

يمكن بدلاً من ذلك إضافة SPIM إلى `PATH`، وعندها يحاول المحرر تشغيل الأمر `spim` مباشرة.

## اختبار التنفيذ

1. شغّل المحرر، وافتح `samples\12_official_basic_execution.bayan`.
2. اضغط **تحليل وترجمة** وانتظر الوصول إلى مرحلة MIPS.
3. اضغط **تنفيذ**.
4. يجب أن ينتقل المحرر إلى مرحلة **نتيجة التنفيذ** ويعرض النص الذي طبعه البرنامج.

إذا ظهر `[RUN001]`، فالمحرر لم يجد MARS أو SPIM. افحص متغير البيئة، ثم أغلق Visual Studio وافتحه من جديد كي يقرأ المتغير المضاف.

## قيد معروف

زر التنفيذ الحالي يلتقط stdout للبرامج غير التفاعلية. البرامج التي تستخدم `اقرأ` وتنتظر إدخالاً ينبغي تشغيل ملفها `.asm` داخل MARS أو SPIM مباشرة، إلى أن تضاف واجهة إدخال runtime داخل المحرر.
