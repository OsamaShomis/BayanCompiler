# مقترحات إعادة تصميم محرر «بيان»

## المشكلة التي يجب حلها

الواجهة الحالية تؤدي المهام المطلوبة، لكنها تظهر كشريط أدوات داكن مزدحم، وأزرارها متساوية الأهمية تقريباً، بينما يجب أن يبرز الإجراء الرئيس: **ترجمة برنامج بيان إلى MIPS**. كما أن عدد تبويبات النتائج كبير ولا يساعد الطالب على فهم المرحلة التي وصل إليها المترجم.

لن تُغيّر إعادة التصميم علاقة المحرر بالمترجم المستقل: يظل المحرر واجهة Windows Forms، ويستدعي CLI، ويعرض artifacts الحقيقية فقط.

## الخيار A — Arabic Compiler Workbench

هذا اتجاه أكاديمي حديث فاتح ومباشر، يشبه مساحة عمل هندسية بدلاً من محرر نص تقليدي. الخلفية رمادية مزرقة فاتحة، والأسطح بيضاء، واللون المميز أزرق بترولي مع تركواز محدود لحالة النجاح.

| العنصر | التصميم |
| --- | --- |
| الشريط العلوي | اسم «بيان» وشارة `MIPS Target` وحالة المترجم، بلا صف طويل من الأزرار. |
| منطقة العمل | الكود على اليمين، ومخرجات المرحلة المختارة على اليسار، مع فاصل قابل للسحب. |
| مسار المترجم | شريط رأسي ثابت: Source → Tokens → LL(1) → Parse Tree → Symbols → TAC → MIPS. |
| الأوامر | زر رئيسي واحد «ترجمة إلى MIPS»، وتحته أزرار ثانوية: فتح، حفظ، تحليل. |
| التشخيصات | لوحة سفلية قابلة للفتح فقط عند وجود أخطاء، مع اللون الأحمر للحالات الخاطئة لا للزينة. |

**يناسب هذا الخيار** المناقشة الأكاديمية؛ لأنه يجعل مراحل المترجم مرئية ومنظمة ويُبقي الواجهة هادئة.

## الخيار B — Bayan Source Studio

هذا اتجاه دافئ ومتميز بصرياً، مستوحى من ورق المخطوطات التقنية لا من الواجهات الداكنة العامة. يستخدم عاجياً خفيفاً، وحبراً كحلياً، ولهجة نحاسية واحدة. النص البرمجي يظهر في مساحة بيضاء واسعة، وتظهر نتائج الترجمة كبطاقات مراحل متتابعة.

| العنصر | التصميم |
| --- | --- |
| الهوية | كلمة «بيان» بخط عربي ثقيل في أعلى اليمين، مع علامة هندسية بسيطة تشبه عقدة شجرة تحليل. |
| تخطيط النتائج | بدلاً من صف تبويبات طويل، قائمة مراحل قابلة للطي في الجانب الأيسر؛ كل مرحلة تعرض حالة نجاح أو خطأ. |
| شريط الأوامر | فتح وحفظ في قائمة ملف صغيرة، بينما الإجراء المركزي هو زر «تحليل وترجمة». |
| القراءة | `Segoe UI` للواجهات العربية و`Consolas` أو `Cascadia Mono` للكود وMIPS. |
| الانطباع | أكاديمي أنيق، أقل تشابهاً مع محررات Visual Studio، وأكثر مناسبة لعرض مشروع جامعي. |

**يناسب هذا الخيار** إذا أردت أن يبدو المشروع مميزاً في العرض أمام الدكتور من دون التضحية بالوضوح.

## الخيار C — Diagnostics Command Center

هذا اتجاه عالي التباين مخصص لمن يريد بيئة شبيهة بأدوات التطوير الاحترافية. الخلفية فحمية هادئة، ومحرر المصدر رمادي داكن، مع ألوان وظيفية مقتصرة: أزرق للمراحل، أخضر للنجاح، أصفر للتحذير، وأحمر للأخطاء.

| العنصر | التصميم |
| --- | --- |
| التخطيط | شريط جانبي للأوامر، محرر مركزي عريض، ولوحة نتائج سفلية ذات تبويبات. |
| الأولوية | يظهر عداد الأخطاء ومرحلة التنفيذ الحالية دائماً في شريط الحالة. |
| الإنتاجية | اختصارات لوحة مفاتيح: `Ctrl+O`، `Ctrl+S`، `F5` للتحليل، و`F6` لتوليد MIPS. |
| التفاصيل | تمييز سطر الخطأ في المحرر، ونسخ MIPS وTAC من لوحات القراءة فقط. |
| الانطباع | تقني قوي، لكنه يحتاج انضباطاً صارماً حتى لا يعود إلى ازدحام الشريط الداكن الحالي. |

**يناسب هذا الخيار** من يريد أداة استخدام يومي أكثر من واجهة عرض أكاديمي.

## التوصية

أوصي بالخيار **B — Bayan Source Studio**. يزيل مشكلة الشريط الداكن المزدحم، ويعطي مشروع اللغة العربية هوية واضحة، ويعرض مراحل المترجم بصورة مرتبة ومقنعة في المناقشة. يمكن أخذ مسار المترجم الرأسي من الخيار A مع هوية الخيار B إذا رغبت في دمج الاتجاهين.

## قرار مطلوب قبل التنفيذ

اختر: **A** أو **B** أو **C**، أو اكتب مثلاً: `B مع مسار مراحل A`. بعد اختيارك سأعيد بناء الواجهة كاملة وفق الاتجاه المعتمد، مع المحافظة على مخرجات CLI الحقيقية واختبارها في Windows Forms.
