# تدقيق أولي لواجهة محرر بيان

## نطاق التدقيق

استند هذا التدقيق إلى بنية `MainForm.cs` و`WelcomeForm.cs` الحالية. لا يُعد بديلاً عن فحص بصري وتشغيلي على Windows؛ لأن بيئة Linux لا تستطيع تحميل Windows Desktop SDK. لذلك تُصنّف البنود البصرية أدناه باعتبارها مخاطر تصميمية مثبتة من الكود أو تحتاج تحققاً يدوياً.

## النتائج البنيوية

| المجال | الملاحظة | الأثر المحتمل | الحكم |
| --- | --- | --- | --- |
| سطح المحرر | يجمع `MainForm` ترويسة وشريط أدوات وتقسيماً عمودياً ومسار مراحل ونتائج تبويب في شاشة واحدة. | كثافة بصرية مرتفعة وصعوبة تحديد نقطة البدء للمستخدم. | يحتاج استبدال تخطيطي. |
| طبقات Dock | توجد طبقات متداخلة من `Panel` و`SplitContainer` و`TableLayoutPanel` و`TabControl`. | تغيير الحجم أو ترتيب إضافة الضوابط قد يولّد تنافساً بصرياً أو قصاً في بعض أبعاد النافذة. | يحتاج تبسيط. |
| التكيف مع الحجم | توجد عروض وارتفاعات ثابتة في عناصر رئيسية، ومنها أزرار ومسار مراحل وشاشة الترحيب. | قد لا تتسع النصوص العربية في نافذة أصغر أو عند تكبير الخط في Windows. | يحتاج اختبار وتحسين. |
| تسلسل الأوامر | توجد أوامر تحرير وتحليل ومراحل متعددة في الشريط نفسه أو قريباً منه. | الإجراء الرئيسي «تحليل وترجمة» لا يحظى بعزل بصري كافٍ. | يحتاج تسلسلاً أبسط. |
| شاشة البداية | تحتوي بطاقة هوية ومساحة أفعال وبطاقة مراحل في تخطيط ثنائي الأعمدة. | العرض الثابت للأزرار قد يكون ضيقاً في نافذة متوسطة. | يحتاج تخطيطاً مرناً أو صفاً واحداً. |
| حالة النتائج | النصوص الفارغة موجودة، لكن لا توجد حالة تشغيل مرئية أو تعطيل موحد للأوامر أثناء CLI. | قد ينقر المستخدم أكثر من مرة أو لا يعرف أن الترجمة تعمل. | يحتاج حالة تحميل وحماية تفاعل. |

## مبادئ الحل

التصميم التالي يجب أن يعتمد سطح محتوى رئيسياً واحداً، وتسلسلاً ثابتاً من ثلاثة أو أربعة صفوف كحد أقصى. يجب أن يُعرض مصدر المستخدم أو artifact واحد في المساحة المركزية؛ لا يجتمع مصدر ومراحل وتبويبات ولوحة تفصيل في مساحة واحدة إلا إذا كان التصميم المختار يعتمد عمودين فقط بشكل صريح.

| عنصر النظام | قاعدة التنفيذ |
| --- | --- |
| المسافات | شبكة 8px: هوامش خارجية 24px، مسافة بين المجموعات 16px، وحشوة داخل البطاقات 16px. |
| الألوان | لون هيكلي واحد، لون تمييز واحد، وألوان حالة وظيفية للنجاح والتحذير والخطأ فقط. |
| النص العربي | `Segoe UI` بحجم 10–12pt للواجهة، وخط ثابت العرض لمخرجات TAC وMIPS. |
| التفاعل | حالة تحويم، تركيز لوحة المفاتيح، تعطيل أثناء التشغيل، ورسالة نجاح/فشل مرئية. |
| إمكانية الوصول | تباين نص مرتفع، تسميات لا تعتمد على اللون وحده، وترتيب تنقل لوحة مفاتيح منطقي. |
| الاستجابة | لا توجد عروض إلزامية كبيرة؛ تستخدم الأعمدة النسبية، أو تنتقل الواجهة إلى صفحة محتوى واحدة عند الضيق. |

## قرار التصميم المطلوب

لا يُنصح بأي رقعة إضافية فوق التخطيط الحالي. يجب اعتماد أحد التخطيطات البنيوية الواردة في `NO_OVERLAP_LAYOUT_OPTIONS.md` قبل التنفيذ التالي، وبالأخص **Compiler Journey** للمناقشة الأكاديمية أو **Source + Inspector** لمن يريد رؤية الكود والنتيجة معاً.
