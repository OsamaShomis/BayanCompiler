# قائمة تحقق محرر «بيان ستوديو» على Windows

هذه القائمة مخصصة للتنفيذ على جهاز Windows يحتوي **Visual Studio 2022** وworkload تطوير سطح المكتب بـ.NET. لا يمكن تشغيل Windows Forms رسوميًا داخل بيئة Linux الحالية لأن حزمة `Microsoft.NET.Sdk.WindowsDesktop` غير مثبتة فيها.

| التحقق | الإجراء | النتيجة المطلوبة |
| --- | --- | --- |
| فتح الحل | افتح `Bayan.sln` في Visual Studio 2022. | تظهر مشاريع Core وCLI وEditor وTests في الحل. |
| إعادة البناء | اختر `Rebuild Solution` في وضع Debug. | ينجح بناء `Bayan.Editor.WinForms` و`Bayan.Compiler.Cli` من دون أخطاء. |
| وجود CLI بجوار المحرر | افتح مجلد `bin\Debug\net6.0-windows`. | توجد ملفات `Bayan.Compiler.Cli.dll` و`.deps.json` و`.runtimeconfig.json` و`Bayan.Compiler.Core.dll`. |
| تشغيل المصدر الافتراضي | شغّل `Bayan.Editor.WinForms` ثم اختر «تحليل البرنامج». | تظهر Tokens وAST وجدول LL(1) وتتبع LL(1) وشجرة التحليل وجدول الرموز من artifacts حقيقية. |
| توليد target code | اختر «توليد MIPS». | يظهر TAC وMIPS Assembly في تبويبيهما، ويشير شريط الحالة إلى مرحلة `MIPS`. |
| اختبار خطأ | احذف فاصلة منقوطة من المصدر ثم نفّذ التحليل. | تظهر تشخيصات CLI في تبويب الأخطاء ويتوقف شريط الحالة عند المرحلة الصحيحة. |
| حفظ ASM | ولّد MIPS ثم اختر «حفظ ASM». | يكتب المحرر ملف `.asm` صالحاً للاختبار في MARS أو SPIM. |
| مظهر الواجهة | راجع شريط الأوامر والعنوان والتبويبات. | تظهر هوية «بيان ستوديو» بألوان الحبر الداكن والورق الفاتح والرموز النصية للأوامر من دون تداخل. |

> لا يعد المحرر متحققاً نهائياً حتى تُنفذ هذه القائمة على Windows وتُسجل نتائجها في قائمة التسليم النهائية.
