# حالة مشروع مترجم لغة «بيان» وخارطة الطريق المتبقية

## الملخص التنفيذي

لغة **بيان** هي لغة برمجة عربية مبسطة. تم بناء نسخة عاملة منها باستخدام C# وWindows Forms. النسخة الحالية تستطيع قراءة البرنامج العربي، وتحليل بنيته، وفحص الأسماء والأنواع، ثم تنفيذه مباشرة بواسطة `Interpreter`.

```text
برنامج بيان عربي
    ↓
Lexer
    ↓
Parser وAST
    ↓
Semantic Analyzer
    ↓
Interpreter
    ↓
الناتج داخل Windows Forms
```

هذه النسخة تسمى عملياً **لغة مفسرة**؛ لأنها تنفذ AST مباشرة. إذا كان المطلوب من الدكتور **مترجماً كاملاً**، فيلزم إضافة تمثيل وسيط IR ثم مولد كود هدف.

## ما لم ينفذ بعد في مترجم كامل

### 1. التمثيل الوسيط IR

لم تنفذ مرحلة **IR** حتى الآن. الوضع الحالي هو:

```text
AST → Interpreter
```

وللمترجم الكامل يصبح:

```text
AST → IR → Code Generator
```

الاختيار المناسب هو **Three-Address Code (TAC)**. مثال:

```text
t1 = 5
س = t1
t2 = س > 3
ifFalse t2 goto L1
print "القيمة كبيرة"
L1:
```

**الملفات المطلوبة:**

```text
Intermediate/IrOpcode.cs
Intermediate/IrInstruction.cs
Intermediate/IrValue.cs
Intermediate/IrGenerator.cs
Intermediate/IrPrinter.cs
```

### 2. Optimization

لم تنفذ مرحلة التحسين. وهي ليست ضرورية غالباً في الإصدار الجامعي الأول، لكنها تأتي بعد IR وقبل توليد الكود.

مثال تحسين بسيط يسمى Constant Folding:

```text
2 + 3 * 4  →  14
```

**الملفات الاختيارية:**

```text
Optimization/ConstantFolder.cs
Optimization/IrOptimizer.cs
```

### 3. Code Generation

لم ينفذ توليد كود هدف بعد. أفضل هدف للمشروع الحالي هو **C#**، لأن المشروع مبني أصلاً باستخدام Visual Studio و.NET 6.

المسار المقترح:

```text
IR → CSharpCodeGenerator → GeneratedProgram.cs
```

مثال التحويل:

```بيان
دع س : عدد = 5؛
اطبع(س)؛
```

إلى:

```csharp
int س = 5;
Console.WriteLine(س);
```

**الملفات المطلوبة:**

```text
CodeGeneration/CodeWriter.cs
CodeGeneration/CSharpCodeGenerator.cs
CodeGeneration/GeneratedCodeResult.cs
Generated/GeneratedProgram.cs
```

### 4. بناء الملف التنفيذي من الكود المولد

هذا تطوير إضافي وليس الخطوة الأولى في Code Generation. بعد توليد `GeneratedProgram.cs`، يمكن فتحه وبناؤه داخل Visual Studio أو باستخدام `dotnet build`.

إذا طلب الدكتور إنتاج DLL أو EXE مباشرة، يمكن لاحقاً استخدام Roslyn أو مشروع C# هدف مستقل. لا يوصى بتوليد Assembly أو x86 مباشرة إلا إذا نص التكليف عليه بوضوح.


## أي نسخة تقدم للدكتور؟

| حالة طلب الدكتور | النسخة المناسبة |
|---|---|
| يريد لغة تعمل وتنفذ البرامج | نسخة Interpreter الحالية. |
| يريد مراحل التحليل فقط | Lexer + Parser + Semantic Analyzer الحالية كافية مع توثيق واضح. |
| يريد IR صراحة | أضف Three-Address Code بعد Semantic Analyzer. |
| يريد Code Generation | أضف مولد C# واحفظ `GeneratedProgram.cs`. |
| يريد Assembly صراحة | يلزم تصميم مولد Assembly منفصل، وهو نطاق أعلى تعقيداً. |

## صياغة التقرير الحالية

> يتكون الإصدار الحالي من مترجم أمامي للغة بيان يشمل التحليل اللغوي، والتحليل النحوي، وبناء شجرة AST، والتحليل الدلالي. بعد ذلك ينفذ البرنامج بواسطة Interpreter. لم تنفذ بعد مرحلة IR ولا Optimization ولا Code Generation، وهي مراحل التطوير التالية لتحويل النظام إلى مترجم مولد لكود هدف.

## صياغة التقرير بعد اكتمال IR وCode Generation

> يتكون مترجم لغة بيان من Lexer، وParser، وAST، وSemantic Analyzer، وتمثيل وسيط Three-Address Code، ومولد كود C# يحول البرنامج العربي إلى ملف مصدر C# قابل للبناء والتنفيذ. تم تنفيذ Optimization بسيطة اختيارياً أو اعتبرت خارج نطاق الإصدار الأول حسب متطلبات التكليف.
