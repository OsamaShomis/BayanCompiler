# نظام تصميم محرر «بيان» الاحترافي

## الفكرة المعتمدة

الواجهة هي **مساحة عمل أكاديمية للمترجمات** لا نسخة من محرر برمجي عام. تنقسم رحلة المستخدم إلى خمس محطات ذات معنى: **المصدر**، و**التحليل**، و**التمثيل الوسيط**، و**الأهداف**، و**النتيجة**. تعرض المساحة المركزية شيئاً واحداً في كل مرة، فلا ينافس الكود جدول LL(1) أو MIPS أو التشخيصات على المساحة نفسها.

## نظام الألوان

| الدور | اللون | الاستخدام |
| --- | --- | --- |
| Navy | `#18344D` | الهوية، عنوان التطبيق، وزر الترجمة الأساسي. |
| Paper | `#FBF8F2` | خلفية التطبيق الهادئة. |
| Surface | `#FFFCF6` | سطح المحتوى والمحرر والبطاقات. |
| Sand | `#EDE3D7` | شريط المحطات والخلفيات الثانوية. |
| Copper | `#BE7E4F` | المحطة أو الاختيار النشط فقط. |
| Ink | `#282D31` | النص الأساسي وبيانات البرنامج. |
| Muted Ink | `#5B5F64` | النص التفسيري ومعلومات السياق. |
| Success | `#236B4A` | النجاح الحقيقي، مثل إنشاء EXE أو تنفيذ ناجح. |
| Warning | `#B7781B` | إعداد مطلوب أو هدف لم يكتمل. |
| Error | `#B42318` | خطأ CLI أو ILAsm أو التنفيذ. |

لا يستخدم اللون الأخضر أو الأحمر كإشارة وحيدة؛ كل حالة تحمل نصاً وصفياً في شارة الحالة.

## الخطوط والاتجاه

| المحتوى | الخط | الحجم |
| --- | --- | --- |
| الهوية والعناوين | Segoe UI Semibold | 18–20 pt للهوية، 16 pt للعنوان الداخلي. |
| الأوامر والنص العربي | Segoe UI | 9–10 pt للأزرار، 10–11 pt للنصوص. |
| بيان المصدر | Segoe UI | 12.5–13 pt، من اليمين إلى اليسار. |
| TAC وMIPS وCIL | Cascadia Mono، ثم Consolas كبديل | 10–10.5 pt، من اليسار إلى اليمين. |

## المناطق الثابتة

```text
60 px   هوية بيان + شارة الحالة
56 px   أوامر الملف والإجراء الأساسي
48 px   المحطات الرئيسية الخمس
40 px   قائمة فرعية محددة بالمحطة الحالية
مرن     عنوان المرحلة + شرح قصير + مساحة محتوى واحدة
46 px   السابق / التالي + حالة المحتوى
```

كل منطقة يملكها `TableLayoutPanel` في صف مستقل. لا يضاف أكثر من عنصر ممتد `DockStyle.Fill` إلى الخلية نفسها، ولا تعتمد الواجهة على صف واحد طويل قابل للتمرير كحل لضيق المساحة.

| المحطة الرئيسة | المراحل الفرعية |
| --- | --- |
| المصدر | المصدر |

## الأزرار والتفاعل

تظهر أوامر الملف (`جديد`، `فتح .bayan`، `حفظ المصدر`) بأسطح فاتحة وحدود نحاسية دقيقة. زر **تحليل وترجمة** هو الإجراء الأساسي الوحيد بلون Navy. لا يتفعل **تنفيذ EXE** إلا عند وجود `program.exe` حقيقي، بينما تنتقل أدوات MIPS إلى محطة الأهداف ولا تنافس زر الترجمة في كل حالة.

يستخدم كل زر حجم لمس لا يقل عن `36px` واسم وصول وتلميحاً. يظهر التركيز بلوحة Navy واضحة، ويصبح الزر المعطل رمادياً مع بقاء النص مقروءاً. أثناء عملية CLI أو التنفيذ تتعطل الأوامر القابلة للتعارض ويظهر شريط تقدم مع نص يصف العملية الجارية.

## الاستجابة لنطاقات النافذة

| عرض النافذة | المعالجة |
| --- | --- |
| 940px فأكثر | المحطات الخمس في صف متوازن، مع قائمة فرعية كاملة. |
| 760–939px | تكبير ارتفاع صف الأوامر والمحطات تلقائياً؛ لا تُقص الأزرار. |
| أقل من 760px | تظل النافذة محمية بـ`MinimumSize` حتى لا يفسد عرض الكود أو العربية. |

## حالات الواجهة

| الحالة | الشارة | المحتوى |
| --- | --- | --- |
| بداية فارغة | جاهز | إرشاد لفتح أو كتابة ملف بيان. |
| تشغيل CLI | يجري التحليل والترجمة | شريط تقدم؛ الأوامر المتعارضة معطلة. |
| نجاح | اكتملت الترجمة | انتقال إلى أحدث artifact صالح. |
| خطأ ترجمة | توقف عند مرحلة محددة | فتح التشخيصات مع النص الحقيقي. |
| EXE غير متاح | يحتاج ILAsm | تشخيص البناء فقط مع بقاء MIPS. |
| نجاح التنفيذ | تم التنفيذ | stdout الحقيقي في محطة النتيجة. |
